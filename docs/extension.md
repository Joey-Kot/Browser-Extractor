# Chrome extension

Development source lives in extension/src. Build output lives in extension/dist and is the directory loaded by Chrome.

Chrome or Chromium 125 or newer is required. Cross-origin out-of-process iframe capture uses the flat child debugger sessions introduced in Chrome 125.

The extension requires debugger, tabs and storage permissions. It creates about:blank first, attaches chrome.debugger, enables the required Page, Runtime and Network domains, and enables `Emulation.setFocusEmulationEnabled` before navigating. This prevents early load and response events from being missed and keeps background job pages visible and focused to page scripts so visibility-gated loaders and rendering can run. It does not activate the tab or change the user's selected tab. Detaching the debugger clears this emulation.

The popup stores the bridge URL and token in chrome.storage.local. browserInstanceId is generated once per extension installation and is also persistent.

Minimal active job metadata is kept in chrome.storage.session. If the service worker restarts and cannot recover executable state, startup cleanup closes the recorded tabs before sync_state. Active in-memory jobs are independent; the extension does not impose a concurrency limit.

Child tabs whose opener belongs to a job are recorded and closed. cleanupJob is idempotent and is the only path that aborts work, detaches CDP, removes owned tabs and clears session storage.

When iframe traversal is enabled, the root debugger session recursively enables `Target.setAutoAttach` for iframe targets. Selected light DOM is described without piercing; eligible same-process Frame documents and Shadow Roots are then fetched individually, while out-of-process frames are read through child sessions. Child sessions wait for a completed document and are checked for loader changes around capture. Child-frame failures are downgraded to traversal warnings, and detaching the root session releases all related sessions.

All request selectors, waits, settling, and scrolling remain in the top-level document. `includeSelectors` defaults to `body`; explicit selectors must initially match and never fall back to that default. A virtualizer may temporarily remove all matching items during scrolling without failing the job. Collection and scrolling normalize selected roots to the same outermost nodes, so a redundant descendant selector cannot re-enable an excluded scroller. The extension discovers the document scroller and visible internal vertical containers related to those roots, including small containers, while skipping excluded subtrees. It advances them with an overlapping viewport-derived step capped at 1500 pixels and rescans after DOM changes. Both modes collect blocks before every scroll. Feed mode streams each new block; document mode also partitions uncovered text and subtrees into context blocks and retains their latest versions by node identity. It returns a final selected-root snapshot when no blocks have disappeared. If virtualization removes or reuses earlier blocks, scrolling document mode merges records and context inside `section[data-extractor-scroll-history]`. New records are inserted before their next surviving neighbor, keeping introductions and conclusions in their original relation to the list. Document mode without scrolling still takes one snapshot. Shadow Root and iframe traversal serializes descendants of selected roots, inferred records, and document context blocks.

Semantic blocks and repeated sibling records take precedence over identified ancestor containers, so a stable `data-id` on a whole thread cannot hide new replies. Automatic deduplication prefers content IDs and semantic permalinks (bookmark or timestamp links), then generic IDs, and otherwise hashes HTML. Ordinary heading links and shared author/profile links never identify an enclosing block. Explicit `link` strategy and `dedupe.selector` retain their requested behavior. Exclusions apply to inferred blocks beneath excluded ancestors as well as their cloned descendants, and all cloned exclusions match the original attributes and structure before image recovery or removals change them.

Reaching the current bottom starts a bounded observation window rather than immediately ending capture. The window is at least 2500 ms or the configured settle period, capped by `loadTimeoutMs`; outstanding top-session Fetch/XHR requests can extend observation up to that load timeout. Continued page mutations cannot keep an individual settle wait open indefinitely. Distance budgets and the overall job deadline remain in force, and capture does not click loading controls or use site-specific rules.

Both capture paths fill each exported image's `src` from an existing non-placeholder `currentSrc`, responsive source set, or lazy-loading attribute (`data-src`, `data-original`, `data-lazy-src`, `data-original-src`, `data-actualsrc`, and their supported source-set variants). A directly adjacent `noscript` containing one fallback image is checked before cleanup; if Trusted Types prevents parsing, only that optional fallback is skipped. Relative URLs use the image's owning document base URL. If the browser has not selected a responsive image, the largest valid width or density candidate is used. Picture candidates must precede the image, match their media condition, and have no type or a known type supported by Chrome 125; an already selected `currentSrc` remains authoritative for other formats. CDP reads resolve captured image backend node IDs instead of matching live DOM order. Recovered images have their exported `srcset` and `sizes` removed, including source sets in their containing picture, so those attributes cannot override the recovered `src`. SVG images without a reliable alternative retain their original responsive attributes. This only rewrites exported content: it does not change live image attributes, trigger lazy loading, or add image readiness waits. The existing `--wait-load` behavior is unchanged.

Beyond navigation and focus emulation, scrolling is the only page interaction performed. The extension does not click load-more controls, paginate, expand disclosure widgets, submit forms, or otherwise interact with page controls.

`background` and `auto` create inactive tabs; `foreground` activates the job tab. Focus emulation keeps page execution visible in all three modes, including when a user leaves a foreground job tab during capture. No mode automatically promotes an inactive job tab.
